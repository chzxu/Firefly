> 在排查真正的故障之前，先建立一个**对照基线**：正常情况下，"文件变大 → 使用率上升 →
> 删除文件 → 使用率回落"这条链路是完整的。案例 02 的异常，就是拿它比出来的。
>
> 说明：以下 `df` 输出为实测结果的归一化版本（按 40G 根分区缩放），**增量与回路量与实测一致**。

## 1. 症状

这不是一个故障，是**主动构造的对照实验**。

- 做了什么：写一个 2G 文件，观察磁盘使用率变化，再删掉观察是否回落
- 目的：给后续的"空间不释放"准备一把标尺
- 影响：无，纯实验

## 2. 环境

- 系统：Ubuntu 22.04（WSL2）
- 文件系统：ext4
- 实验时间：2026-11-15

## 3. 步骤与输出

### 3.1 记录基线

```bash
df -h /
```

```text
Filesystem      Size  Used Avail Use% Mounted on
/dev/sdX        40G  3.2G   35G   9% /
```

**基线：已用 3.2G，使用率 9%。**

### 3.2 造一个 2G 文件

```bash
fallocate -l 2G /tmp/hog.img
df -h /
```

```text
Filesystem      Size  Used Avail Use% Mounted on
/dev/sdX        40G  5.2G   33G  13% /
```

**观察：使用率 9% → 13%，正好增加 2G。**

> `fallocate` 是按块直接分配空间，不做实际写入，比 `dd` 快几个数量级。

### 3.3 确认文件真实存在

```bash
ls -lh /tmp/hog.img
```

```text
-rw-r--r-- 1 <user> <user> 2.0G Nov 15 /tmp/hog.img
```

> `-h` 是 human-readable，不加的话大小显示为字节数（2147483648）。

### 3.4 删除并复查

```bash
rm -f /tmp/hog.img
df -h /
```

```text
Filesystem      Size  Used Avail Use% Mounted on
/dev/sdX        40G  3.2G   35G   9% /
```

**观察：使用率 13% → 9%，空间立即释放。**

## 4. 结论

| 阶段 | 变化 | 说明 |
|---|---|---|
| 基线 | 3.2G / 9% | — |
| 写入 2G 后 | 5.2G / 13% | 增量 = 2G |
| 删除后 | 3.2G / 9% | **立即回落** |

**正常删除 = 空间立刻回来。这是判断"异常"的标尺。**

## 5. 这条基线有什么用

- 给出判断标准：删除后 `df` 应该**立刻回落**
- 案例 02 里没有回落，就是拿这条标准比出来的
- 以后遇到"磁盘满了但找不到大文件"，第一步都是先确认这个基线是否正常

## 附 · 命令速查

| 命令 | 作用 | 注意 |
|---|---|---|
| `df -h` | 文件系统层面的空间 | 统计块设备，不是文件 |
| `du -sh` | 目录/文件的占用 | 遍历目录，看不到已删除但被打开的文件 |
| `fallocate -l 2G` | 快速分配空间 | 比 `dd` 快得多 |
| `ls -lh` | 确认文件存在与大小 | `-h` 人类可读 |
